## Project Overview

Tony Rosen's portfolio website - a single-page application built with Astro, featuring a simple editorial hero, smooth scrolling with Lenis, and comprehensive analytics integration.

**Tech Stack:**

- **Framework:** Astro 5 with React integration
- **Styling:** Tailwind CSS 4 (with Preline UI plugin)
- **Animations:** Lightweight CSS and browser-native animations
- **Smooth Scroll:** Lenis
- **Analytics:** PostHog, Google Analytics 4, LinkedIn Insight Tag, RB2B, Leadfeeder (Dealfront)
- **Performance:** Deferred analytics and interaction-first loading

## Architecture

### View Switching System

This is a **single-page application** with client-side view switching (not Astro's built-in routing). All content lives on one page (`/`) and switches views via hash URLs:

- `/` or `/#home` - Home view (ManyHatsDeskHero + ImpactCharts + Experience)
- `/#resume` - no view: opens the contact dialog as a resume request (Resume links in the nav, footer and metrics do the same)
- `/#portfolio` - Portfolio view
- `/#styleguide` - Style guide view
- `/#colophon` - Colophon view

**How it works:**

1. Navbar dispatches `view-change` custom events
2. `index.astro` listens for these events and shows/hides view containers
3. Each view change triggers analytics pageviews (GA4 + PostHog)
4. Hash changes update browser history without page reload

### Home Experience

- `ManyHatsDeskHero.astro` is the homepage hero ("Many Hats"): a statement on the left whose role word, marker underline and color change with the hat, and Anthony at his desk on the right, swapping hats on a timer or via the glass dock. Copy lives in `src/data/many-hats-roles.ts` (`hero`); headlines are 3 lines and subheads ~2, and Tony approves all copy changes.
- The hat swap itself is `src/scripts/many-hats/hat-stage.ts` + `src/components/many-hats/HatStage.astro`, using images generated by `scripts/many-hats-web-v19.py` and `scripts/many-hats-web-desk-v21.py`.
- Earlier homepage designs are preserved as archived previews under `/versions` rather than as unmounted components in the live component set (see "Version Archive" below). The previous `ManyHatsHero.astro` hero now lives there as the "Hi, I'm Anthony" preview, and the former slam hero + Three.js background are reconstructed at `/versions/stone-slam` (its rollback path is also documented in `docs/archive/slam-hero-rollback.md`).

### Version Archive

Past homepage designs are kept as previewable archives so they stay one click away without cluttering the live site.

- **Gallery:** `/versions` lists each design (the live one plus archived previews) with thumbnails from `public/version-thumbs/`.
- **Archived previews:** `/versions/stone-slam` (the "Tired of the fluff?" hero with the 3D cotton-ball scene and slam animation) and `/versions/hi-im-anthony` (the simple serif greeting hero). Each is reconstructed from the version that was live at a specific commit.
- **Self-contained components:** version-specific components live under `src/components/versions/` (e.g. `stone-slam/` holds that era's `Hero`, `ThreeScene`, `SlamSection`, fallback and worker). The stone slam preview is why `three` is a dependency; it is bundled only on that route, not the live site. `SlamSection` loads anime.js from a CDN at runtime.
- **Kept off the live site:** every `/versions` page is `noindex`, excluded from the sitemap (filter in `astro.config.mjs`), and returns 404 in production via a `VERCEL_ENV === "production"` guard, so Astro omits it from the production build. The pages still build in local dev and Vercel preview deployments, so they remain easy to preview.
- Adding a version: drop its component(s) under `src/components/versions/`, add a `src/pages/versions/<slug>.astro` route (with the production guard and a `VersionBadge`), and add an entry to the `versions` array in `src/pages/versions/index.astro`.

### Performance Optimizations

The site is optimized for fast loading and excellent Core Web Vitals scores:

1. **Critical CSS Inlining:**
   - Essential styles inlined in `<head>` to eliminate render-blocking CSS
   - Main stylesheet loads asynchronously
   - Lenis critical styles inlined to prevent FOUC

2. **Deferred JavaScript Loading:**
   - All analytics scripts (PostHog, Google Analytics, LinkedIn Tag, RB2B) defer using `requestIdleCallback`
   - Lenis smooth scrolling initialization deferred until after page load
   - Reduces Total Blocking Time (TBT) from 4,100ms to ~60ms on mobile

3. **Lenis Smooth Scrolling:**
   - Deferred initialization using `requestIdleCallback`
   - Auto-pauses after 5 seconds of inactivity (helps Lighthouse)
   - Stops when tab is hidden
   - Restarts on any user interaction

4. **Font Loading / typography tokens:**
   - Fonts are defined only in `src/styles/global.css` and documented in the style guide (`StyleGuide.astro`, "Typography"). Components use the tokens, never a family name.
   - Display serif: `--font-display` (Tailwind `font-display`) = Newsreader SemiBold, weight 600 only, self-hosted at `public/fonts/newsreader/` (Latin subset, `font-display: swap`, with a metric-matched Georgia fallback so the swap causes no layout shift). Pages that open with a display headline preload the woff2.
   - Body/UI: the sans stack on `<body>` in `Layout.astro` (`Inter, system-ui, …`). Inter is not loaded as a web font, so visitors without it installed see their system sans.

5. **Cache Headers:**
   - Static assets cached for 1 year with `immutable` flag (via `public/_headers`)
   - HTML pages revalidate on each request
   - Configured for Netlify/Vercel deployment

### Hero Motion

The hat flies off and the next one lands (WAAPI, compositor-only transforms/opacity). The text block disappears when a swap starts and fades back in with the incoming hat; nothing inside it animates on its own. Only the old and new dock dots animate. Reduced motion switches instantly.

### Analytics Integration

**Five tracking services** (loaded only after analytics consent):

1. **Google Analytics 4** (`G-7LRLJTJG4L`)
2. **PostHog** (configured in `PostHog.astro`)
3. **LinkedIn Insight Tag** (`LinkedInTag.astro`)
4. **RB2B** (company-level visitor identification, `RB2B.astro`)
5. **Leadfeeder / Dealfront** (company-level visitor identification, `Leadfeeder.astro`)

RB2B and Leadfeeder both do company-level visitor identification and run
side by side intentionally, so their free tiers can be compared; either can be
removed on its own by dropping its component from `Layout.astro`.

**Virtual pageviews:** Each view switch tracks as a pageview with custom path/title.

**Job-search events:** `contact_click`, `resume_request`, `linkedin_click`, and `portfolio_open` are sent to GA4 and PostHog by `JobSearchAnalytics.astro`.

### Dark Mode

- **Strategy:** Class-based (`class="dark"`)
- **Storage:** `localStorage.theme`
- **Fallback:** System preference (`prefers-color-scheme`)
- **Init:** Inline script in `Layout.astro` prevents flash of wrong theme
- **Icons:** Dual favicons for light/dark mode

### Privacy & Compliance

- **Cookie Banner:** `CookieBanner.astro` (shown on first visit)
- **Privacy Policy:** `/privacy` page (`src/pages/privacy.astro`)
- Cookie consent controls analytics opt-in/opt-out

## Important Patterns

### Handling Undefined Data

Components like `ImpactCharts.astro` defensively handle potentially undefined data to prevent runtime errors. Always check for null/undefined before accessing nested properties.

### Accessibility

- **Contrast ratios:** Use `text-slate-400` (not `text-slate-500`) in dark mode for sufficient contrast
- **Heading hierarchy:** Semantic headings (h1-h6), avoid skipping levels
- **Footer labels:** Use `<p>` tags, not `<h4>`, for non-heading footer labels

### Scroll Interactions

The hero's paper tint eases toward each hat's color. Keep its reduced-motion behavior intact when changing the section.
